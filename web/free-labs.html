Start here before touching live systems.

These are safe, public learning lanes for owned hardware and controlled lab environments. They give CyberFlipper a professional content foundation while pointing serious teams toward FLLC workshops and implementation help.

SCOPE_FIRST.txt
[1] Use hardware you own or have written permission to test.
[2] Prefer passive observation, documentation, and harmless demo fixtures.
[3] Never publish credential capture, persistence, evasion, or live-target instructions.
[4] If a lab can affect RF, access control, or production equipment, isolate it.
[5] Every lesson should produce a defensive takeaway.
01 · Flipper SD Hygiene

Build a clean SD-card folder tree, separate experiments from releases, and document what each asset does before copying it to a device.

  • Deliverable: manifest + changelog
  • Defense: repeatable inventory
02 · IR Remote Baseline

Capture and label IR commands from devices you own, then produce a clean reference sheet for home-lab automation and troubleshooting.

  • Deliverable: IR command table
  • Defense: asset documentation
03 · NFC Tag Anatomy

Compare blank NTAG cards, business-card tags, and demo tags. Record UID format, memory size, and safe NDEF use cases.

  • Deliverable: tag inventory
  • Defense: card awareness
04 · Proxmark Notes

Create a lab notebook template for owned test cards: card type, reader behavior, screenshots, risk notes, and remediation ideas.

  • Deliverable: assessment template
  • Defense: access-control review
05 · GPIO Bring-Up

Wire a harmless sensor or display module, document voltage, pinout, library version, and failure modes before expanding the circuit.

  • Deliverable: pinout sheet
  • Defense: safe electronics practice
06 · Badgelife Build Log

Plan a badge-style PCB project: microcontroller choice, BOM, power budget, enclosure idea, artwork, and test checklist.

  • Deliverable: build log
  • Defense: engineering traceability
07 · Tamper-Evident Inspection

Study seals, labels, bags, and document marks. Record normal appearance, failure modes, and how chain-of-custody notes should look.

  • Deliverable: inspection checklist
  • Defense: integrity practice
08 · RF Listening Ethics

Map legal/ethical boundaries before using SDR or SubGHz tools. Focus on weather, beacons, owned remotes, and public documentation.

  • Deliverable: band plan notes
  • Defense: compliance mindset
09 · Payload Documentation

Write payload specs as defensive test cases: purpose, scope, prompt, log output, rollback, and expected blue-team detection.

  • Deliverable: test-case card
  • Defense: auditable training
10 · Aerospace Telemetry Mindset

Create a telemetry checklist for a balloon/payload-style project: sensor source, cadence, units, timestamps, calibration, and recovery plan.

  • Deliverable: telemetry plan
  • Defense: reliability thinking
11 · FLLC Portfolio Writeup

Turn one lab into a customer-facing case study: problem, constraints, build, validation, screenshots, and next-step services.

  • Deliverable: portfolio page
  • Defense: professional proof
12 · Workshop Kit Plan

Package a classroom kit: parts list, cost, learning objectives, safety notes, instructor timing, and assessment rubric.

  • Deliverable: workshop outline
  • Defense: repeatable education
